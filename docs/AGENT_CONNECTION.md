# 在页面中接入智能体

[文档首页](index.md) · [English](en/agent-connection.md)

“交通仿真 → 智能体接入”用于给当前实验分配模型、车辆、Memory 和 Skill，然后直接开始控制。模型调用运行在 SimHarness 后端，桌面只提交配置和显示状态，无需另外启动 Agent 命令行。

## 启动和接入

1. 按[安装与运行](GETTING_STARTED.md)启动后端和普通交通界面。已有旧版本进程需要重启才能使用新增页面与接口。
2. 在仿真配置中勾选 **等待外部 Agent 控制**，然后开始仿真。实验保持运行状态，并等待动作推进。
3. 打开左侧 **智能体接入**，或点击运行页面的 **接入智能体 →**。页面自动关联当前实验 ID，并显示当前帧和接入状态。
4. 配置至少一个控制组，选择模型和车辆；按需开启 Memory、选择 Skill。
5. 点击 **检查配置**，然后 **开始接入**。检查只验证实验状态、配置和后端环境变量是否存在，不发送模型请求、不验证服务连通性。
6. 点击 **查看仿真**返回地图。接入继续在后端执行，地图沿用现有仿真帧更新；再次进入接入页可查看状态、暂停或结束。

无需手工复制实验 ID。切换工作区或创建新实验时，页面跟随桌面当前关联的实验，不会把旧实验的异步响应显示到新实验上。

## 控制组与模型

每个控制组配置一个模型，可以控制多辆车；添加不同控制组即可让不同模型共同控制一个实验。每轮收集各组动作后只推进一次 SUMO。

| 配置 | 含义 |
| --- | --- |
| 配置来源 | 手工填写，或载入“资产中心 → 智能体配置”中保存的 API 设置；修改本次控制组不会修改资产 |
| 接入方式 | 远程 API、本地 OpenAI 兼容服务、Jev |
| 服务地址、模型 ID | 复用现有模型封装的配置；API/本地地址包含需要的版本路径，不包含 `/chat/completions` |
| Key 环境变量名称 | 例如 `DEEPSEEK_API_KEY`，填写变量名；本地无需鉴权时可留空 |
| 模型超时 | 单次模型请求超时，范围 1–300 秒 |
| Jev 加减速 | Jev 离散加速/减速动作对应的加速度幅值 |

Key 从**后端进程的环境**读取。只在桌面终端设置 Key 无效；为已运行的后端新增或修改环境变量后，应重新启动后端。页面和会话配置仅保存变量名。

本地模型同样通过 HTTP 服务调用，不会在页面内加载模型权重。页面支持三种已有封装；自定义 Python 控制器继续使用 [Agent Harness 命令行](../src/trafficverse/agent_harness/README.md)。

## 车辆分配与观测

- **指定车辆 ID**：勾选当前帧车辆，或输入逗号分隔的 ID。尚未出发的车辆也可以提前填写，在它出现后自动匹配。
- **全部车辆（包括后续进入）**：控制当前及后续进入的所有车辆。此模式只能有一个控制组，避免归属冲突。
- 同一车辆不能分配到多个控制组。未分配的车辆、未返回动作的车辆、返回非法动作的车辆继续使用 SUMO 控制。
- 页面不使用 L0–L5 作为默认分组。车辆列表来自当前真实仿真帧。

初始第 0 帧没有车辆快照时，可以先填写已知 ID 或选择全部车辆。接入后先用空动作推进一帧获取局部观测，这一步也计入帧数上限。中途接入已有帧的实验时直接读取当前帧，不额外预推进。

**局部观测半径**为本次会话统一参数，使用现有“自车 + 指定范围内车辆”的映射。模型输入不改回全局帧。

## Memory 和 Skill

两者现在是与“模型与上下文”同级的独立面板，使用更大的标识和独立状态，默认均不启用。

- **Memory · 车辆记忆**：按车辆 ID 保存最近若干轮的观测、请求动作和下一帧结果。范围为每车 1–1000 轮，按组设置。
- **Skill · 驾驶风格**：可选谨慎驾驶、**均衡驾驶**、鲁莽驾驶。均衡驾驶使用已有 `human_normal` Skill。一般为一组选择一种驾驶风格，避免相互矛盾的要求。

启用后，每轮将 Memory 与 Skill 加入对应车辆上下文，再交给模型判断。继续复用现有失败处理：Memory/Skill 调用失败时忽略该部分；模型调用失败或动作不合格时，该轮相应车辆由 SUMO 控制。详见 [Memory 与 Skill](AGENT_MEMORY_SKILL_DESIGN.md)。

## 逐轮输入与输出

开始接入后，页面自动切到 **逐轮输入 / 输出**，也可随时切回 **接入配置**。
默认使用 **信息卡片** 模式，原有表格和 JSON 页签完整保留在 **原始详情** 中。
切换模式不会重新调用模型，也不会改变所选轮次或仿真状态。

卡片左侧是轮次与控制组列表，右侧展示该轮车辆数、有效动作、SUMO 控制数量和推理耗时。
选择车辆后，可分别查看 **周边观测、Memory、Skill、车辆控制** 四个信息块，下方是模型输出摘要和本组校验后的动作。
卡片只整理已有响应，不生成额外模型解释；“SUMO 控制”数量只在该轮已提交后显示。

每个控制组每轮对应一条记录，显示输入帧号、模型、车辆数、耗时、有效动作数和 SUMO 回退车辆数。
同一帧有多个控制组时会分别列出。初始获取观测的空动作步不调用模型，因此没有决策记录。

选中记录后，可以查看：

- **输入 · 观测 / Memory / Skill**：分配到该组的局部观测和实际装配的车辆上下文；Memory、Skill 在较长的观测前展示。
- **模型请求**：发给模型的请求正文，包括提示词。Jev 的同轮多次请求会合并列出。
- **原始输出**：模型服务返回内容；格式错误的响应也保留，便于排查回退原因。
- **通过校验的动作**：模型输出经过校验后的动作。空数组表示本组无有效外部动作。

推理开始后即可查看输入，输出随调用完成更新。推理状态和提交状态分开显示：
**已返回**不表示已经推进仿真；**已提交**表示动作批次已交给仿真执行，不保证每个动作都被底层接受。
暂停或结束导致的未执行结果标记为 **已丢弃**。动作错误和运行结果仍以仿真事件为准。

默认跟随最新记录，每页最多 20 条。点击某条记录后停止跟随，可用“较早记录 / 较新记录”翻页。
记录写入 `artifacts/agent-sessions/<experiment_id>/<session_id>/`，页面关闭或轮询较慢不会漏掉已经保存的轮次。
每栏最多保留 128,000 字符，超过时明确提示截断；不记录认证请求头，当前调用的 Key 会从请求和响应文本中去除。
若文件写入失败，页面提示历史记录可能不完整，仿真继续运行。

卡片的结构化输入概要单独保存在记录的 `input_preview` 中，不依赖对已截断原文的解析。
为控制体积，每轮最多保存 100 辆车的概要；每车保留最近的 3 辆邻车、最近 2 轮记忆和最多 3 个 Skill，
每个 Skill 指令最多 1,200 字符，发生省略时页面会提示。旧记录缺少概要时仍可查看原始详情。
这些限制只影响记录展示，不改变发送给模型的完整输入。

此页展示由桌面接入功能托管的会话，不包含独立 CLI 的模型调用。暂停继续保留当前记录；
结束后重新接入建立新记录集。页面只查询后端当前会话，后端重启不恢复会话，但已写入的记录文件仍在。

## 暂停、结束与运行限制

| 操作 | 结果 |
| --- | --- |
| 开始接入 | 从实验当前帧开始读取观测、推理、批量提交动作 |
| 暂停接入 | 不再提交尚未执行的动作；正在进行的模型调用返回后进入暂停 |
| 继续接入 | 从停留帧继续，并重新计算本次帧数预算 |
| 达到最多推进帧数 | 自动暂停，可检查结果或继续 |
| 结束接入 | 等待当前调用返回，丢弃其未执行动作，释放会话控制权 |

暂停或结束接入不会停止实验，也不会让 SUMO 自动自由运行，实验仍等待外部动作。要结束实验，请在仿真运行页面点击停止。若动作已经提交，正在推进的那一帧会正常完成。

暂停期间保留该会话的控制权，其他客户端调用 `/step` 或 `/local-step` 会得到 409；需要换用外部程序时先结束接入。暂停后以相同配置继续会保留按车 Memory，修改配置或结束后重新开始会建立新的 Memory。

每轮额外间隔是推理和步进之外的等待时间，不是模型超时。多个控制组当前依次调用，因此一轮耗时包含各组的推理时间。暂停/结束中的请求仍受各模型超时约束，界面不会阻塞。

切换页面或关闭桌面不会取消后端会话；它会继续执行到帧数上限、实验结束或接入错误。后端关闭时清理会话，未提交的模型结果不会继续推进实验。会话配置和 Memory 当前仅保存在后端进程内，重启不恢复。

## REST 接口

以下路径前缀为 `/api/v1/experiments/{experiment_id}/agent-session`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET` | 状态、配置、当前车辆、帧号 |
| `POST /check` | 检查配置与环境，不调用模型 |
| `POST /start` | 开始或恢复后台会话，立即返回 |
| `POST /pause` | 请求暂停 |
| `POST /stop` | 请求结束接入 |
| `GET /decisions` | 分页读取决策摘要；`before_id` 游标、`limit`（默认 20，最大 50） |
| `GET /decisions/{record_id}?session_id=...` | 读取指定会话的记录详情，防止新旧会话编号混淆 |

`check` 和 `start` 使用同一个类型化配置；`pause`、`stop` 不需要配置。完整字段以生成的 [OpenAPI](../contracts/openapi.yaml) 为准。运行中的会话不能重复启动或直接修改配置，先暂停再调整。
