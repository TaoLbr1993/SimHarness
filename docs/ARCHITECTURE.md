# 系统架构与数据流

[English](en/architecture.md)

本文描述当前 SUMO 二维主流程。较早的 [系统设计](SYSTEM_DESIGN.md) 还包含 CARLA 联仿目标和验收设计，阅读时应区分目标与已验证的功能。

## 组成部分

| 部分 | 职责 |
|---|---|
| SUMO 与 TraCI 适配 | 推进交通仿真，提供车辆状态并接收控制请求 |
| 应用层 | 管理实验和仿真步进，从全局帧生成车辆局部观测 |
| REST / WebSocket API | 提供资源管理、同步步进与实时消息 |
| 桌面界面 | 创建实验，展示仿真状态和历史结果 |
| 外部 Agent Harness | 按配置分配车辆，调用模型或控制器，汇总并提交动作 |

## 外部控制的数据流

```text
SUMO 当前交通状态
       │
       ▼
应用层按距离生成每辆车的局部观测
       │
       ▼
外部 Agent：观测 + 可选 Memory / Skill → 决策
       │
       ▼
一次提交多辆车的动作 → SUMO 推进一步 → 返回新观测
```

桌面页面通过后端获取全局展示数据，Agent 则可通过 `/local-step` 获取选定车辆的局部观测。两者查看的是同一实验。局部观测目前只是基于 SUMO 世界状态的距离筛选，不模拟传感器。

外部控制实验等待外部程序发起每一步；Agent 推理慢会延长现实时间，但仿真不会在等待期间自行推进。未提交动作的车辆由 SUMO 控制。SUMO 决定动作的实际执行结果，动作请求不等同于一定执行成功。

## Agent 与仿真的边界

应用层不依赖特定大模型。外部程序可以直接调用 [同步步进 API](EXTERNAL_STEP_API.md)，也可以使用内置 [Agent Harness](../src/trafficverse/agent_harness/README.md)。车辆选择、模型服务配置、Memory 和 Skill 均由 Agent 侧管理。

Memory 当前为按车辆隔离的进程内短期记录；Skill 当前是提供给模型的文本指引。两者均默认关闭，也不改变 SUMO 作为交通状态来源的角色。

## CARLA

仓库保留 SUMO–CARLA 同步、ROI 和窗口托管相关实现，但当前桌面运行页面未接入 CARLA 窗口。真实环境中的联仿和展示仍需集成及验证，不应视作已完成的二维主流程能力。
